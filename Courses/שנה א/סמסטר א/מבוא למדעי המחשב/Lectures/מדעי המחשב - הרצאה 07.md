# Structs
- Data aggregate consisting pf elements of different types.
- Structure is a type defined by the programmer.
- need to declare a struct for using it, then it can be used as any other primitive type.
- no memory is allocated upon initialization.
### typedef
in short: give a type a new name.

### typedef struct
```C
typedef struct Student{
	char name[10];
	int id;
}Student;

// can be used like this now:

int main(){
	Student s = {"Moshe", 1111};
	struct Student s1 = {"Moshe",1111};
}
```

### Accessing members: operator "."
```C
typedef struct Student{
	char name[10];
	int id;
}Student;

// can be used like this now:

int main(){
	Student s = {"Moshe", 1111};
	printf("%s, %d", s.name, s.id);
}
```

**You cant initialize fields in struct declaration**
**struct type cannot have static members**

in general: 
$`{}sizeof(struct){}`$ $`{}\geq{}`$ $`{}\left(sizeof \sum sizeof(struct.element) \right){}`$ 

### accessing members: operator ->
```C
int main(){
	Student s = {"Moshe", 1111};
	Student *ps = &s;
	// instead of doing:
	(*ps).id = 1212; // change the value of s.id thorugh the pointer ps
	// we can use this openrator instead:
	ps->id=1212;
}
```
### rule of thumb:
if we have a pointer, use an arrow (->),
if we have a regular variable, use a dot (.) 

```C
int main() { 
	Student s[3] = {{"Moshe", 1111}, {"Michal", 1212}, {"Efrat", 1234}}; 
	Student *ps = s;
	
	// all these refer to the same thing:
	s[3].id = 10;
	(p+1) -> id = 20;
	(*(p+1)).id = 1213;
}
```

### passing a struct to a function: value vs. address
- pass by value: a copy of the struct - all fields copied to local variable
- by address: address of the variable, like always
```C
typedef struct{
	char name[10];
	int id;
}Student;

void change1(Student s){
	s.id = 5;
}
void change2(Student *s){
	s->id = 5;
}

Student a = {"Avi",3};
change1(a); // a.id = 3
change2(&a); //a.id = 5;
```

# Dynamic Memory Allocation
- **Arrays**: size must be known at compilation time

- **Problems**:
	- Array may be too small - not enough room for all the elements
	- array may be too big - waste of memory
- **The Solution**: Use Dynamic Memory Allocation (DMA)
	- Create the array at run-time
		- After knowing the required number of elements


### malloc
• Dynamically allocates memory at run-time
	• Input: number of requested bytes
• Returns the address of allocated memory block
• All the allocation functions use the library
```C
int size, *pint;
printf(“how many integers?”); 
scanf(“%d”, &size); 
pint = malloc(size*sizeof(int)); 
for (int i=0; i<size; i++)
	pint[i] = i;
```

### calloc
• Dynamically allocates memory at run-time, and “clears” it.
	• Initializes it with 0s.
• Input: number of elements, size of each element.
• Returns the address of allocated memory block (also void $`{}*{}`$).

# Memory Allocation
• Reminder: program’s (process) virtual memory.
	• Stack segment is dedicated to local variables.
	• Data segment is used for global and static variables. 
	• Text – for the instructions.
• Dynamic memory is allocated in the heap.

# Freeing the memory

• Dynamic memory is allocated in the heap 
	• It is not deleted when the end of a block is reached 
• Programmer’s responsibility to explicitly delete it 
• Use free 
	• Gets the first address of an allocated memory block, and frees it
```C
free(first_address);
```

# Reallocating memory
• Advantage of dynamic memory allocation: enables reallocation 
	• Increase/decrease the old allocation size 
• Done using the realloc function
```C
void *realloc(void *ptr, new_size)
```
• If there is enough space 
	• extend the old allocation 
• Else 
	• Allocate new size 
	• Copy the old data to the new place 
	• Free the old allocation (should not be used anymore) 
• Return the first address of the new allocation 
	• Same as initial, or different

# realloc: Preserve the old pointer upon failure

• realloc May move the block to a new address 
• Old values remain, up to the smaller size 
• New extra elements are uninitialized
